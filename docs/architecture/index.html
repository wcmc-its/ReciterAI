View 1 · the one-glance landscape

System context

The picture for newcomers: ReciterAI reads the WCM publication corpus from ReciterDB and a frozen taxonomy, runs a seven-stage LLM pipeline against AWS Bedrock (with an OpenAI fallback), and publishes to two S3 buckets + DynamoDB. The Scholars Profile System pulls from those — ReciterAI is upstream and ships independently.

ReciterDB's publication data originates from PubMed via the ReCiter disambiguation engine (upstream of this diagram). View 2 · the data flow

Processing pipeline

What happens between corpus and artifact. score_publications runs a two-pass screen (cheap Haiku recall → calibrated Sonnet scoring); subtopics are discovered then assigned; rollup_by_cwid builds faculty profiles; a separate daily enrichment job adds synopsis + impact; spotlight synthesizes a curated lede; and the hierarchy publisher composes the canonical artifact. View 3 · how it's deployed

AWS runtime topology

The deployed shape: five EventBridge cron rules drive a Step Functions hot path, a Fargate enrichment task, and three Lambdas. They reach Bedrock (models), DynamoDB (state), S3 (artifacts) and Secrets Manager (config), read the corpus from ReciterDB, fall back to OpenAI on a content filter, and alert Teams. Infrastructure is single-file JSON (D-10) until the CDK migration threshold fires.

Bedrock auth differs by compute: Lambdas use the task IAM role; the Fargate enrichment task authenticates with a long-lived AWS_BEARER_TOKEN_BEDROCK (no bedrock:InvokeModel grant on its role — a missing token fails loud). View 4 · the integration surface

Publish contract — the hand-off to SPS

The interface that matters to anyone integrating: ReciterAI publishes, the Scholars Profile System pulls. Two S3 channels carry the canonical hierarchy and spotlight artifacts (versioned for production, latest/ for dev, a co-published JSON Schema, and a manifest.json whose sha256 lets the ETL short-circuit when nothing changed); DynamoDB carries the record-level data. ReciterAI never calls SPS.

One-way hand-off: ReciterAI is upstream and ships independently; it does not call SPS, depend on SPS at runtime, or know about Prisma / MySQL. Contract source-of-truth lives in docs/hierarchy-contract.md and docs/spotlight-contract.md.

S3 publish contract

  1. Versioned + latest. Every publish writes an immutable v{ISO-date}/ prefix (retained indefinitely) and overwrites latest/. Production pins a version; dev tracks latest/.
  2. sha256 short-circuit. manifest.json carries the artifact hash; the SPS ETL reads the manifest first and skips the whole upsert when the hash is unchanged.
  3. Schema-validated. The JSON Schema is co-published with the artifact; the ETL validates before it writes, so a malformed publish fails closed.
  4. diff.json. A structured change signal — added / removed / renamed subtopics, reassigned-PMID count, and an editorial_only flag — so consumers can react proportionally.

DynamoDB record types (single table reciterai)

PK prefixCarries
TOPIC#{id}per-pub topic scores + subtopic assignments
FACULTY#{cwid}ranked topic / subtopic rollups, h-index
IMPACT#{pmid}synopsis (≤95 ch) + impact score (0–100)
SPOTLIGHT#…curated lede + supporting publications
STAGE#…run audit + content-addressed skip-cache (internal)

Records carry taxonomy_version, so a taxonomy bump triggers targeted recompute rather than a full rebuild.
