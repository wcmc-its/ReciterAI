View 3 · how it's deployed

AWS runtime topology

The deployed shape: five EventBridge cron rules drive a Step Functions hot path, a Fargate enrichment task, and three Lambdas. View 4 · the integration surface

Publish contract — the hand-off to SPS

The interface that matters to anyone integrating: ReciterAI publishes, the Scholars Profile System pulls. Two S3 channels carry the canonical hierarchy and spotlight artifacts (versioned for production, latest/ for dev, a co-published JSON Schema, and a manifest.json whose sha256 lets the ETL short-circuit when nothing changed); DynamoDB carries the record-level data. ReciterAI never calls SPS.

ProducerPublished channelSPS ETLConsumer
Edge types — colour = relationship · dashed = out-of-band / async
ReciterAI writesSPS ETL pullsloads into SPS

One-way hand-off: ReciterAI is upstream and ships independently; it does not call SPS, depend on SPS at runtime, or know about Prisma / MySQL. Contract source-of-truth lives in docs/hierarchy-contract.md and docs/spotlight-contract.md.

S3 publish contract

  1. Versioned + latest. Every publish writes an immutable v{ISO-date}/ prefix (retained indefinitely) and overwrites latest/. Production pins a version; dev tracks latest/.
  2. sha256 short-circuit. manifest.json carries the artifact hash; the SPS ETL reads the manifest first and skips the whole upsert when the hash is unchanged.
  3. Schema-validated. The JSON Schema is co-published with the artifact; the ETL validates before it writes, so a malformed publish fails closed.
  4. diff.json. A structured change signal — added / removed / renamed subtopics, reassigned-PMID count, and an editorial_only flag — so consumers can react proportionally.

DynamoDB record types (single table reciterai)

View 5 · what it actually does

Functional overview — how ReciterAI works

The plain-English picture: ReciterAI reads every WCM publication and, against a frozen research-domain map, understands each paper on three axes — its domain (Axis 1), its theme within that domain (Axis 1.5), and the tools & methods it used (Axis 2) — and writes a one-line synopsis plus an impact score. The labelled papers roll up into a profile for each scholar; a spotlight picks the strongest theme and writes a short lede; and everything is published to the public faculty profiles. Each box names the question it answers.

Three orthogonal axes describe each paper: Axis 1 (~67 domain topics, inductive + human-approved), Axis 1.5 (subtopics within each domain), and Axis 2 (a methods & tools taxonomy, built separately). The domain map is generated once and frozen — papers are scored against it, never the other way around. ReciterAI is upstream of the Scholars Profile System and ships independently.

View 6 · the technology layers

Technical stack

Every technology, grouped by layer. Pure Python 3.12 (boto3, the OpenAI SDK, SQLAlchemy, jsonschema) calls AWS Bedrock for Claude inference, with an OpenAI gpt-5.1 fallback. It runs as a Docker image on ECS Fargate and three Lambdas, orchestrated by Step Functions + EventBridge cron; persists to DynamoDB and S3 while reading the corpus from ReciterDB; and is configured by Secrets Manager + checked-in JSON/YAML. There is no runtime API — it publishes artifacts and exits.

View 7 · run-to-run dynamics

Stability & drift — keeping it from jiggling

The dynamics the other six views freeze out. Three things jiggle every run: re-clustering relabels subtopics, the upstream author set churns, and daily grounding (synopsis + impact) moves — each of which would otherwise churn subtopic ids, spotlight ledes, and rankings. A band of stabilizers damps it: durable ids (match-or-mint keeps an id across rebuilds), the reconcile ladder (overlap → centroid → LLM, cached by input-hash), the STAGE# skip-cache, the lede/relabel skip gates, and the rotation selector. Watchdogs then measure the residual drift and alert.

Jitter source / alert sinkStabilizerWatchdog (daily Lambda)Durable state (DynamoDB)
Edge types — colour = relationship · dashed = out-of-band / async
run-to-run jitterdaily grounding churnverdict / controlpersists / emits a recordobserves runs / alerts

Honest mapping: relabel jitter is damped by the identity stabilizers; daily grounding by the lede-skip gate (grounding-PMID equality); author churn is re-absorbed by membership reconcile and independently flagged by the onboarding watchdog's R9 churn check. The durable-ID store is pipeline-internal recognition memory — SPS still consumes slug ids; the slug→durable repoint is the remaining brick-D step (#191). Every stabilizer is idempotent: an unchanged input input_hash skips the stage entirely.
