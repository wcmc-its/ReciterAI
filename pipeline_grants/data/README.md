# Curated opportunity inputs (`pipeline_grants/data/`)

A hand-curated list of funding **awards/prizes** WCM wants surfaced in GrantRecs,
a second ingest source alongside `grants_gov.py`. The curated path
(`pipeline_grants/ingest_curated.py`) maps each row to an `Opportunity`
(`models.py`), runs it through the **same** score → `build_grant_item` → persist
path, and lands `GRANT#` DynamoDB items in the `reciterai` table that are
indistinguishable from API-sourced opportunities downstream (SPS GrantRecs).

Unlike the Grants.gov firehose, this list is human-vetted, so the curated ingest
**deliberately bypasses the denoise gates** (`regex_gate` would drop these on
"prize"/"medal" and `judge_opportunity` is prompted to mark prizes
`is_research=false`). It synthesizes `is_research=True` and derives
`appeal_by_stage` from the curated `Career Stage` column instead of the LLM judge.

## Files

```
wcm_curated_opportunities_<YYYY-MM-DD>.csv   # raw WCM export (input)
wcm_curated_opportunities_enriched.csv       # generated by enrich_wcm_curated (input to ingest)
```

The raw export is the WCM-maintained spreadsheet, saved as CSV. It carries a
one-line banner (`Document Last Updated on …`) above the real header row;
`wcm_curated.read_curated_csv` skips it automatically (it locates the header by
the `Award Name` column, so the banner may be present or absent).

## Columns (raw export)

`read_curated_csv` keys on the header names below; extra columns pass through
untouched. `opportunity_id` is `wcm_curated:<slug(Award Name + Sponsoring
Organization)>-<6-char hash>` — stable across re-exports (row number is not used)
and collision-proof, so genuine duplicate rows (same name + sponsor) collapse to
one item rather than fork or double-spend Bedrock.

| Column | Required | Maps to `Opportunity` | Notes |
|---|---|---|---|
| `Award Name` | ✅ | `title` | also feeds `opportunity_id`; a row with a blank name is skipped |
| `Sponsoring Organization` | — | `sponsor` | also feeds `opportunity_id` |
| `Award Field` | — | — | coarse field; used to build a synopsis (see enrichment) |
| `Career Stage` | — | `eligibility_raw` | free text → `appeal_by_stage` via `career_stage_to_appeal` heuristic |
| `Award Amount` | — | `estimated_funding` | largest `$`/comma number in the cell → int; `None` if no number |
| `Nomination Deadline` | — | `due_date` | first `Month DD, YYYY` → ISO `YYYY-MM-DD`; blank/`Rolling` = continuous |
| `Website` | — | `source_url` | fetched during enrichment to build the synopsis |

`program_type` is set to `"award"` and `status` to `"open"` for every row.
`topic_vector` and `appeal_by_stage` are generated by the pipeline (production
scorer + curated career-stage map) — never put them in the CSV.

## Synopsis is generated, not provided

The raw export has only an award name + a coarse field, but the topic scorer
needs descriptive text. `enrich_wcm_curated` fetches each `Website`, summarizes it
with Bedrock into a 2–4 sentence research-focused synopsis, and writes
`*_enriched.csv` (original columns + `synopsis` + `enrich_status`). It is
resumable (good rows are cached, fallbacks re-attempted) and never drops a row:
an unfetchable site falls back to a name+field+sponsor summary, then to a bare
field-based synopsis.

## Running it

1. Enrich the raw export (one-time; ~199 web fetches + Bedrock):
   ```
   python -m pipeline_grants.enrich_wcm_curated \
       --in  pipeline_grants/data/wcm_curated_opportunities_<YYYY-MM-DD>.csv \
       --out pipeline_grants/data/wcm_curated_opportunities_enriched.csv
   ```
2. Ingest the enriched CSV. Writes `GRANT#` items to the `reciterai` table, so
   run with **SPS-staging** credentials (account `665083158573`) first; the table
   is selected by your ambient AWS creds/region, so confirm them before running.
   Use `--dry-run` to build + report without writing to DynamoDB/S3.
   ```
   python -m pipeline_grants.ingest_curated \
       --csv pipeline_grants/data/wcm_curated_opportunities_enriched.csv --dry-run
   ```
3. SPS operator: `npm run etl:dynamodb` then `npm run search:index`.
4. Verify in `/edit/find-researchers` with a real `wcm_curated:<id>`.
