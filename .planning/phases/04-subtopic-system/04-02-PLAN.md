1. `DISCOVERY_SYSTEM_PROMPT` — static Sonnet system prompt instructing:
   - Input: parent topic label + description, list of ~N activities each as `{pmid, title, synopsis, impact_score, relevance_score}`
   - Output STRICT JSON: `{"subtopics": [{"id": "<slug>", "label": "...", "description": "...", "seed_pmids": [...], "coverage_estimate": 0.XX}], "uncovered": [<pmid>...], "total_activities": N, "coverage_pct": 0.XX}`
   - Rules: 8-15 clusters, each ≥3 activities (review item #1); each cluster has 1-2 sentence description; clusters must reflect what's actually in data (CLAUDE.md taxonomy design principle); leave activities unassigned rather than forcing them into a weak cluster; IDs use `{topic_prefix}_{slug(label)}` format where topic_prefix is supplied by caller; no IDs must overlap with existing top-level taxonomy IDs.
   - No markdown fences. Pure JSON only.

2. `DISCOVERY_EXTENSION_PROMPT` — extension-pass prompt template used when initial coverage <85% (D-01). Accepts placeholders `{current_subtopics_json}`, `{uncovered_activities_json}`, `{extension_cap}`. Instructs: "Previous pass achieved X% coverage. Given these existing subtopics and uncovered activities, propose additional subtopics (up to <extension_cap>) that capture the uncovered set. Do NOT modify existing subtopic IDs. Respect the same ≥3 activities/cluster rule."

```
[{"pmid": 12345, "title": "...", "synopsis": "...", "impact_score": 72, "relevance_score": 0.85}, ...]

Produce subtopics now.
```

Create `discover_subtopics.py` at repo root with this CLI interface:

```
python discover_subtopics.py --topic <topic_id> [--min-activities 30] [--extension-cap 30] [--output-dir .planning/phases/04-subtopic-system] [--dry-run]
```

Algorithm:
1. Parse args. Load `taxonomy_v2.json` to verify topic_id exists and get label/description.
2. Query DynamoDB `TOPIC#<topic_id>` partition for all items with SK prefix `SCORE#` and score ≥0.3 (decode via `parse_score_sk` helper — port from PM's `shared.ts::parseScoreSk`). Extract `{pmid, title, synopsis, impact_score, score}` per item. Deduplicate by pmid.
3. If `len(activities) < min_activities` (default 30 per D-01 cold-start floor), exit code 2 with message `"Topic {topic_id} has only N activities (floor=30); skipping. Add to excluded_topics when assembling hierarchy.json."`
4. Build user message via `BUILD_DISCOVERY_USER_MESSAGE`; call Sonnet via `bedrock_converse(SONNET_MODEL, DISCOVERY_SYSTEM_PROMPT, user_msg, temperature=0.0)`. Strip JSON fences defensively (reuse pattern from Phase 2's `stripJsonFences`).
5. Parse JSON response. Validate: 8-15 subtopics, each with required keys, each with ≥3 seed_pmids. If any cluster <3, drop it and re-add those pmids to `uncovered`.
6. Compute coverage: `assigned_pmids = union of all seed_pmids across clusters`; `coverage = len(assigned_pmids) / len(activities)`.
7. If `coverage < 0.85` AND current cluster count < `min(2 * initial_N, 2 * extension_cap)`: invoke `DISCOVERY_EXTENSION_PROMPT` with uncovered activities. Append new clusters. Re-check coverage. Stop when ≥85% OR at 2× cap (D-01).
8. Assemble output JSON per `hierarchy-schema.md`:
```json
{
  "topic_id": "aging_geroscience",
  "topic_label": "Aging & Geroscience",
  "subtopics": [ ... ],
  "uncovered_pmids": [ ... ],
  "total_activities": N,
  "coverage_pct": 0.XX,
  "generated_at": "<ISO UTC>",
  "sonnet_model_id": "us.anthropic.claude-sonnet-4-6",
  "passes_executed": 1 or 2
}
```
9. Write to `{output_dir}/hierarchy_draft_{topic_id}.json`. Log to stdout: topic, activity count, cluster count, coverage, passes, total Sonnet input/output tokens (from Converse response usage).
10. If `--dry-run` set, skip writing; print summary only.

Error handling: On Bedrock errors reuse `utils.bedrock_client` retry; on JSON parse failure after fence-strip, write raw response to `{output_dir}/hierarchy_draft_{topic_id}.raw.txt` and exit code 3.

Cluster ID generation: `{topic_id_prefix}_{slugify(label)}` where `topic_id_prefix = topic_id.split('_')[0]` (e.g., `aging_geroscience` → prefix `aging`). Slugify = lowercase, replace non-alphanumeric with underscore, strip leading/trailing underscores. Add `# WARNING: IDs are NOT stable across recomputes — D-06` comment above the slug function.
