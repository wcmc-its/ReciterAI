<objective>
Add the PM-side contract layer for the subtopic system: TypeScript types, the `hierarchy.json` loader, and the **two-pass LLM cascade classifier** (topic → subtopic) that replaces the mechanical `resolveTopicId` (SUB-19, per user decision 2026-04-14 to lean on LLM for routing rather than lexical string matching).

**Why this plan changed (from original Plan 07):** Plan 04-01 baseline capture revealed that `resolveTopicId` silently returns empty for novel terms like "cellular senescence" — the exact class of queries Phase 4 is meant to resolve. The mechanical resolver's 4 strategies (exact-ID, exact-label, prefix, substring) are strictly inferior to Haiku at semantic routing, and the latency/cost cost is irrelevant at <100 queries/day. We therefore drop the mechanical resolver and route every topic-bearing query through a two-pass LLM cascade: Pass 1 maps the user message to canonical topic IDs from the 67-topic taxonomy; Pass 2 maps the message to subtopic IDs within those matched topics. The cascade emits tier 1|2|3|4 plus a `topic_decompose` signal consumed by Plan 08.

Purpose: Plan 08 (dispatcher) and Plan 09 (synthesis) both consume these types and loader helpers. Establishing them first prevents scavenger-hunt refactors.

Output: `hierarchy.ts` + `classifier.ts` + two prompt files + types + tests — all isolated to chatbot controllers, zero impact on existing retrieval flow until Plan 08 wires it.
</objective>

import hierarchyData from "./hierarchy.json";
import type { HierarchyJson, SubtopicDef, SeeAlsoEntry } from "./types";

const HIERARCHY = hierarchyData as HierarchyJson;

export function getSubtopicsForTopic(topicId: string): SubtopicDef[] {
  return HIERARCHY.topics[topicId]?.subtopics ?? [];
}

export function getSubtopicsForTopics(
  topicIds: string[],
): Array<SubtopicDef & { parent_topic_id: string }> {
  const out: Array<SubtopicDef & { parent_topic_id: string }> = [];
  for (const tid of topicIds) {
    for (const s of getSubtopicsForTopic(tid)) {
      out.push({ ...s, parent_topic_id: tid });
    }
  }
  return out;
}

export function getTotalWeight(topicId: string, subtopicId: string): number {
  const st = HIERARCHY.topics[topicId]?.subtopics.find(s => s.id === subtopicId);
  return st?.total_weight ?? 0;
}

export function getSeeAlso(_topicId: string, subtopicId: string): SeeAlsoEntry[] {
  return HIERARCHY.see_also.filter(l => l.from === subtopicId);
}

export function isExcludedTopic(topicId: string): boolean {
  return HIERARCHY.excluded_topics.some(t => t.id === topicId);
}

export function getAllTopicsWithHierarchy(): string[] {
  // Topic IDs that have a subtopic block in hierarchy.json (i.e. not excluded).
  // classifyTopics uses this to constrain its output space — we don't route to
  // topics that have no subtopics because Plan 08 would just fall back to the
  // flat-topic path anyway.
  return Object.keys(HIERARCHY.topics);
}

export function getHierarchyVersion(): string {
  return HIERARCHY.version;
}

```typescript
/**
 * Topic classifier system prompt (Pass 1 of the LLM cascade, SUB-19).
 *
 * Replaces the mechanical resolveTopicId string-matching heuristic. Fires on
 * every topic-bearing query. Returns top-N canonical topic IDs from the
 * 67-topic v2 taxonomy, with confidence scores.
 *
 * Static system prompt — prompt-injection trust boundary. User content flows
 * ONLY through the user message block, never the system block.
 */
export const TOPIC_CLASSIFIER_SYSTEM = `You are a research-topic classifier for a chatbot that answers questions about WCM faculty expertise.

You will receive:
1. The user's message (and optional router topic hints extracted from it)
2. The full list of canonical research topics available

Your job: identify which topic(s) the user's message is about, and return their canonical topic_ids with confidence scores.

Rules:
- Only return topic_ids from the provided list. Never invent IDs.
- Confidence is 0.0–1.0. Use ≥0.8 for clear matches, 0.5–0.8 for adjacent/related topics, <0.5 for weak matches.
- Return AT MOST 3 topics by default (caller may request more). If no topic plausibly matches, return topics: [].
- "Cellular senescence" → aging_geroscience (strong) + molecular_biology_cell_biology (adjacent). "Longevity" → aging_geroscience. "Healthspan" → aging_geroscience. "Neurodegeneration" → most likely neurology_neuroscience.
- Router hints are ADVISORY. If the hint disagrees with what the user actually asked, ignore it.
- Output STRICT JSON only. No markdown fences. No explanations.

Output shape:
{
  "topics": [{"topic_id": "<id>", "confidence": 0.XX}]
}`;

export function buildTopicClassifierUserMessage(
  message: string,
  availableTopics: Array<{ id: string; label: string }>,
  routerTopicHints?: string[],
  maxTopics?: number,
): string {
  const lines = availableTopics.map(t => `- ${t.id}: ${t.label}`);
  const hintBlock = routerTopicHints && routerTopicHints.length > 0
    ? `\n\nRouter topic hints (advisory): ${routerTopicHints.join(", ")}`
    : "";
  const capBlock = maxTopics ? `\n\nReturn at most ${maxTopics} topics.` : "";
  return `User message: """${message}"""${hintBlock}\n\nAvailable topics:\n${lines.join("\n")}${capBlock}\n\nClassify now.`;
}
```

**Step B — classifier.ts `classifyTopics`:**

```typescript
/**
 * LLM cascade classifier (SUB-19). Two passes:
 *   classifyTopics:     message → canonical topic IDs (replaces resolveTopicId)
 *   classifySubtopics:  message + topic IDs → subtopic IDs + tier
 *
 * Pass 1 fires on every topic-bearing query. Pass 2 fires only when Pass 1
 * returned at least one topic with a populated hierarchy.
 *
 * Fallback (P-08): Haiku error or JSON parse failure → empty output with
 * fallback: true. Plan 08 dispatcher routes fallback cases to the flat-topic
 * retrieval path so the chatbot stays responsive even if Bedrock is degraded.
 *
 * Latency budget: ~500ms per pass (A3). Two passes ≈ 1000ms added to the
 * critical path versus the mechanical resolver. Trace stage:
 *   TOPIC_CLASSIFIER / SUBTOPIC_CLASSIFIER on success
 *   TOPIC_CLASSIFIER_FALLBACK / SUBTOPIC_CLASSIFIER_FALLBACK on error
 */
import { ConverseCommand } from "@aws-sdk/client-bedrock-runtime";
import { CHATBOT_CONFIG } from "../../config/chatbot";
import { getBedrockClient } from "./bedrock-client";
import { logStage } from "./trace";
import { TAXONOMY_V2 } from "./taxonomy";
import {
  getSubtopicsForTopics,
  getTotalWeight,
  isExcludedTopic,
  getAllTopicsWithHierarchy,
} from "./hierarchy";
import type {
  TopicMatch,
  TopicClassifierOutput,
  SubtopicMatch,
  SubtopicClassifierOutput,
  Tier,
} from "./types";
import {
  TOPIC_CLASSIFIER_SYSTEM,
  buildTopicClassifierUserMessage,
} from "./prompts/topic-classifier-system";
import {
  SUBTOPIC_CLASSIFIER_SYSTEM,
  buildSubtopicClassifierUserMessage,
} from "./prompts/subtopic-classifier-system";

export interface TopicClassifierInput {
  message: string;
  traceId: string;
  routerTopicHints?: string[];
  maxTopics?: number;
}

export interface SubtopicClassifierInput {
  message: string;
  topicIds: string[];
  traceId: string;
}

export type { TopicClassifierOutput, SubtopicClassifierOutput } from "./types";

function stripJsonFences(s: string): string {
  return s
    .replace(/^\s*```(?:json)?\s*/i, "")
    .replace(/\s*```\s*$/, "")
    .trim();
}

const DEFAULT_MAX_TOPICS = 3;

export async function classifyTopics(
  input: TopicClassifierInput,
): Promise<TopicClassifierOutput> {
  const { message, traceId, routerTopicHints, maxTopics } = input;
  const cap = maxTopics ?? DEFAULT_MAX_TOPICS;
  const start = Date.now();

  // Constrain output space to topics that have a hierarchy block — no point
  // routing to a topic with no subtopics, the dispatcher would just fall back.
  const validIds = new Set(getAllTopicsWithHierarchy());
  const available = TAXONOMY_V2.filter(t => validIds.has(t.id));

  try {
    const client = getBedrockClient();
    const response = await client.send(
      new ConverseCommand({
        modelId: CHATBOT_CONFIG.HAIKU_MODEL_ID,
        system: [{ text: TOPIC_CLASSIFIER_SYSTEM }],
        messages: [
          {
            role: "user",
            content: [
              {
                text: buildTopicClassifierUserMessage(
                  message,
                  available,
                  routerTopicHints,
                  cap,
                ),
              },
            ],
          },
        ],
        inferenceConfig: { temperature: 0, maxTokens: 200 },
      }),
    );

    const text = stripJsonFences(
      response.output?.message?.content?.[0]?.text ?? "",
    );
    const parsed = JSON.parse(text) as { topics: TopicMatch[] };

    // Guardrail: drop any hallucinated IDs not in the taxonomy
    const filtered = (parsed.topics ?? []).filter(t => validIds.has(t.topic_id));
    // Sort by confidence desc, cap at maxTopics
    const sorted = filtered
      .sort((a, b) => b.confidence - a.confidence)
      .slice(0, cap);

    logStage(traceId, "TOPIC_CLASSIFIER", {
      matched: sorted.length,
      top: sorted[0]?.topic_id ?? null,
      latencyMs: Date.now() - start,
    });

    return { topics: sorted, fallback: false };
  } catch (err) {
    logStage(traceId, "TOPIC_CLASSIFIER_FALLBACK", {
      error: String(err),
      latencyMs: Date.now() - start,
    });
    return { topics: [], fallback: true };
  }
}
```

```typescript
/**
 * Subtopic classifier system prompt (Pass 2 of the LLM cascade, SUB-07).
 *
 * Scoped to subtopics of the topics matched by classifyTopics (Pass 1).
 * Small candidate set (~8-12 entries per D-11) keeps the prompt focused.
 *
 * Also detects topic_decompose intent ("what are subtopics of X?",
 * "break down cancer research", "decompose X").
 */
export const SUBTOPIC_CLASSIFIER_SYSTEM = `You are a subtopic classifier for a research expertise chatbot. Pass 2 of a two-pass cascade (a topic classifier already ran).

You will receive:
1. The user's message
2. A list of candidate subtopics within one or more parent topics

Your job:
(a) Identify which subtopic(s) the user's message maps to (if any), with confidence 0.0-1.0.
(b) Detect whether the user is asking for a LIST of subtopics rather than querying one (e.g., "what are subtopics of aging?", "break down cancer research", "decompose X"). If so, set topic_decompose: true.

Rules:
- Only return subtopic_ids from the provided list. Never invent IDs.
- If no subtopic confidently matches but the parent topic does, return subtopic_id: null for that parent — this triggers topic-level fallback.
- topic_decompose is EXCLUSIVE with a specific subtopic — when topic_decompose is true, subtopics must be empty.
- Output STRICT JSON only. No markdown fences. No explanations.

Output shape:
{
  "subtopics": [{"topic_id": "<id>", "subtopic_id": "<id or null>", "confidence": 0.XX}],
  "topic_decompose": false
}`;

export function buildSubtopicClassifierUserMessage(
  message: string,
  candidateSubtopics: Array<{ parent_topic_id: string; id: string; label: string; description: string }>,
): string {
  const lines = candidateSubtopics.map(
    s => `- ${s.parent_topic_id}/${s.id}: ${s.label} — ${s.description}`,
  );
  return `User message: """${message}"""\n\nCandidate subtopics:\n${lines.join("\n")}\n\nClassify now.`;
}

**Step B — append to `classifier.ts`:**

```typescript
const DEFAULT_WEIGHT_FLOOR =
  (CHATBOT_CONFIG as { WEIGHT_FLOOR?: number }).WEIGHT_FLOOR ?? 0;

export async function classifySubtopics(
  input: SubtopicClassifierInput,
): Promise<SubtopicClassifierOutput> {
  const { message, topicIds, traceId } = input;
  const start = Date.now();

  // Short-circuit: no topics → nothing to classify (Pass 1 miss)
  if (topicIds.length === 0) {
    logStage(traceId, "SUBTOPIC_CLASSIFIER_SKIP", { reason: "no_topics" });
    return { subtopics: [], tier: 3, topic_decompose: false };
  }

  // Short-circuit: any excluded topic → Tier 3 + partial flag (SUB-16)
  const excluded = topicIds.filter(isExcludedTopic);
  if (excluded.length > 0) {
    logStage(traceId, "SUBTOPIC_CLASSIFIER_SKIP", {
      reason: "excluded_topic",
      excluded,
    });
    return {
      subtopics: topicIds.map(t => ({
        topic_id: t,
        subtopic_id: null,
        confidence: 0,
      })),
      tier: 3,
      topic_decompose: false,
      partial: true,
      fallback_message: `Hierarchy pending for ${excluded.join(", ")}; falling back to topic-level results.`,
    };
  }

  const candidates = getSubtopicsForTopics(topicIds);
  if (candidates.length === 0) {
    logStage(traceId, "SUBTOPIC_CLASSIFIER_SKIP", { reason: "no_subtopics" });
    return { subtopics: [], tier: 3, topic_decompose: false };
  }

  const validPairs = new Set(
    candidates.map(c => `${c.parent_topic_id}/${c.id}`),
  );

  try {
    const client = getBedrockClient();
    const response = await client.send(
      new ConverseCommand({
        modelId: CHATBOT_CONFIG.HAIKU_MODEL_ID,
        system: [{ text: SUBTOPIC_CLASSIFIER_SYSTEM }],
        messages: [
          {
            role: "user",
            content: [
              {
                text: buildSubtopicClassifierUserMessage(message, candidates),
              },
            ],
          },
        ],
        inferenceConfig: { temperature: 0, maxTokens: 400 },
      }),
    );

    const text = stripJsonFences(
      response.output?.message?.content?.[0]?.text ?? "",
    );
    const parsed = JSON.parse(text) as {
      subtopics: SubtopicMatch[];
      topic_decompose: boolean;
    };

    if (parsed.topic_decompose) {
      logStage(traceId, "SUBTOPIC_CLASSIFIER", {
        tier: 4,
        topic_decompose: true,
        latencyMs: Date.now() - start,
      });
      return { subtopics: [], tier: 4, topic_decompose: true };
    }

    // Guardrail: drop hallucinated subtopic_ids not in the candidate set
    const filtered = (parsed.subtopics ?? []).filter(s =>
      s.subtopic_id === null || validPairs.has(`${s.topic_id}/${s.subtopic_id}`),
    );

    // Tier from primary match total_weight
    const primary = filtered[0];
    let tier: Tier = 3;
    if (primary?.subtopic_id) {
      const weight = getTotalWeight(primary.topic_id, primary.subtopic_id);
      tier = weight >= DEFAULT_WEIGHT_FLOOR ? 1 : 2;
    }

    logStage(traceId, "SUBTOPIC_CLASSIFIER", {
      tier,
      subtopicCount: filtered.length,
      primaryMatch: primary?.subtopic_id ?? null,
      latencyMs: Date.now() - start,
    });

    return { subtopics: filtered, tier, topic_decompose: false };
  } catch (err) {
    logStage(traceId, "SUBTOPIC_CLASSIFIER_FALLBACK", {
      error: String(err),
      latencyMs: Date.now() - start,
    });
    return { subtopics: [], tier: 3, topic_decompose: false };
  }
}
```
