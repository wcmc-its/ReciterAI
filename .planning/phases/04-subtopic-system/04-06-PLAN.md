  <action>
Create `backfill_topic.py` at repo root.

CLI: `python backfill_topic.py --topic <id> [--skip-review] [--min-activities 30]`

Algorithm:
1. Validate topic_id exists in `taxonomy_v2.json`.
2. Check pre-count of activities: query TOPIC#<id> count of items scoring ≥0.3. If <`min_activities`, print skip-message with activity count, write to stdout a line `EXCLUDED:<topic_id>:<count>:below_cold_start_floor`, and exit 0.
3. Invoke `subprocess.run(["python", "discover_subtopics.py", "--topic", topic_id], check=True)`. If exit != 0, record failure in `backfill_log.md` and exit 1.
4. Load `hierarchy_draft_<id>.json`. If `--skip-review` NOT set AND `review_status != "approved"`, print human-review prompt and exit 2 (user intervenes, then rerun with same args to resume). If `--skip-review` set (risky, documented), inject `"review_status": "auto_approved"` and continue — but log a warning. Additionally, when --skip-review is used, append a single line to `.planning/phases/04-subtopic-system/artifacts/backfill_log.md` formatted `SKIP_REVIEW | <topic_id> | <UTC ISO-8601 timestamp> | authorized_by: <os.getenv("USER", "unknown")> | pre-authorized for lower-priority topic` — grep-checkable audit trail.
5. Invoke `subprocess.run(["python", "assign_subtopics.py", "--topic", topic_id, "--resume"], check=True)`.
6. Invoke `subprocess.run(["python", "aggregate_subtopic_scores.py", "--topic", topic_id], check=True)`.
7. Read `total_weights_<id>.json` (from Pass 3) and inject `total_weight` + `activity_count` (from DynamoDB count of items with primary_subtopic_id == subtopic_id) back into each subtopic in the draft. Write augmented draft to `hierarchy_augmented_<id>.json`.
8. Append summary line to `backfill_log.md`.

Document the 4 subprocess calls in a docstring; note each is a separate process so env (AWS creds) must be inherited. Use `subprocess.run(..., check=True)` so failures propagate.
  </action>

Create `backfill_all.py` at repo root.

CLI: `python backfill_all.py [--dry-run] [--only-verdict-check] [--skip-pm-copy] [--continue-on-error]`

Algorithm:
1. **Verdict gate**: Read `.planning/phases/04-subtopic-system/aging_pilot_results.md`. Search for line matching `## Verdict: GO`. If not present, print error and exit 2. (`--only-verdict-check` exits 0 immediately after this succeeds.)
2. **Topic ordering**: Query DynamoDB to get activity count per topic (count items with SK prefix `SCORE#` and relevance score ≥0.3 per TOPIC# partition). Exclude `aging_geroscience` (already done by Plans 02/03/04). Sort remaining 66 topics by count descending.
3. **Per-topic loop**: For each topic in order, run `subprocess.run(["python", "backfill_topic.py", "--topic", t])`. Capture stdout/stderr to `backfill_log.md`. If `--continue-on-error` set, record failure and proceed; else abort.
4. **Assemble hierarchy.json**:
   - Start with `{"version": "subtopic_v1", "generated_at": ISO_NOW, "taxonomy_version": "taxonomy_v2", "excluded_topics": [], "topics": {}, "see_also": []}`
   - For each topic in taxonomy_v2: if `hierarchy_augmented_<id>.json` exists, load subtopics[] (with activity_count + total_weight) into `topics[id].subtopics`. Else add to `excluded_topics[]` with reason and activity_count.
   - Write to `.planning/phases/04-subtopic-system/hierarchy_full.json`.
5. **See-also generation**: `subprocess.run(["python", "generate_see_also.py", "--input", "hierarchy_full.json", "--output", "see_also_full.json"])`. Merge `see_also[]` from output into `hierarchy_full.json`.
6. **Copy to PM worktree**: Unless `--skip-pm-copy`, `cp hierarchy_full.json ReCiter-Publication-Manager/controllers/chatbot/hierarchy.json`. Print instruction: "Now commit the PM artifact via commit-to-subrepo:
   ```
   cd ReCiter-Publication-Manager
   git add controllers/chatbot/hierarchy.json
   git commit -m 'feat(04): add subtopic hierarchy.json (Plan 06 full backfill)'
   ```
   This is a subrepo commit on the `feature/chatbot-runtime` branch per CLAUDE.md."
7. Summary print: N topics processed, N excluded, total Sonnet cost, total Haiku cost, elapsed time, total DynamoDB WCUs consumed.

`backfill_log.md` format:

Update after each topic completes.

`--dry-run`: skip all LLM + DynamoDB calls; print order + estimated cost.
