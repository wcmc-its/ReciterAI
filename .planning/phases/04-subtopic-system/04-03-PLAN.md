Create `assign_subtopics.py` at repo root.

CLI: `python assign_subtopics.py --topic <topic_id> [--concurrency 15] [--confidence-floor 0.3] [--draft-path .planning/phases/04-subtopic-system/hierarchy_draft_<topic_id>.json] [--limit N] [--resume]`

Algorithm:
1. Load approved hierarchy draft. Assert `review_status == "approved"` — exit 2 if not.
2. Query DynamoDB TOPIC#<topic_id> partition for all activities at score ≥0.3 (same filter as Pass 1).
3. If `--resume` flag set, SKIP activities that already have `primary_subtopic_id` attribute present (idempotent per research §Pass 2 batching).
4. For each activity, prepare (pmid, topic_meta, subtopic_defs) payload. Submit to `ThreadPoolExecutor(max_workers=concurrency)`. Worker function:
   a. Call `bedrock_converse(HAIKU_MODEL, ASSIGNMENT_SYSTEM_PROMPT, user_msg, temperature=0.0, max_tokens=400)`
   b. stripJsonFences on response (defensive — Plan 02-08 pitfall)
   c. Parse JSON. Filter to assignments with `confidence >= --confidence-floor` (default 0.3)
   d. If filtered list is empty, skip write (activity stays unassigned → Tier 3 fallback per D-02)
   e. Sort filtered by confidence descending. `primary_subtopic_id = list[0].subtopic_id`. Handle ties via `_resolve_primary_on_tie`:
      - If top-2 confidences are within 0.001, read `total_weight` from hierarchy draft's current state (if not yet known — Pass 1 draft has seed_pmid counts, use that as proxy); pick higher. If still tied, pick alphabetically lower id.
   f. `subtopic_ids = [a.subtopic_id for a in filtered]`
   g. `subtopic_confidences = {a.subtopic_id: a.confidence for a in filtered}`
   h. Call `update_activity_subtopics(pk=f"TOPIC#{topic_id}", sk=activity.sk, subtopic_ids, primary_subtopic_id, subtopic_confidences)`
5. Print progress every 50 activities: `assigned/total, failures, elapsed s`.
6. On `bedrock_converse` exception: log to stderr, continue (exponential backoff in `utils.bedrock_client` already handles retries; if still failing, skip this activity — it can be re-run via `--resume`).
7. At end, print summary: total activities, assigned count, unassigned count, coverage, median confidence, estimated Haiku cost.

Add `_resolve_primary_on_tie(confidences_dict, subtopic_defs, hierarchy)` helper as module-level function with docstring referencing review item #2 default. Note: total_weight is not known definitively until after Pass 3; for Pass 2 use `seed_pmid_count` from Pass 1 draft as total_weight proxy.

Algorithm (arithmetic-only, NO LLM call):
1. Query DynamoDB TOPIC#<topic_id> partition. Extract per item: `faculty_uid` (strip `cwid_` prefix to get person_identifier), `primary_subtopic_id`, `score` (relevance), `impact_score`.
2. For items where `primary_subtopic_id` is `None`/absent, skip (D-02: unassigned activities contribute zero).
3. Compute `article_score = (impact_score / 100) ** 1.2 * relevance_score ** 1.4` per item — formula must match CLAUDE.md + `itemToTopicMatch` in PM's shared.ts EXACTLY (P-10 drift pitfall).
4. Accumulate in nested dict: `scores[person_identifier][primary_subtopic_id] += article_score`.
5. Compute set of faculty touched: `touched_pids = scores.keys()`.
6. For EACH `pid` in `touched_pids`:
   - Call `clear_faculty_subtopic_scores_for_topic(pid, topic_id)` (D-06 wholesale replacement)
   - Call `update_faculty_subtopic_scores(pid, topic_id, scores[pid])`
7. Also compute `total_weight[subtopic_id] = sum of article_scores with that primary`; print as table + write to `.planning/phases/04-subtopic-system/total_weights_<topic_id>.json` — needed by Plan 05 pilot gate and Plan 07 for hierarchy.json `total_weight` field.
8. Log: faculty touched count, subtopic score sum per subtopic, top-5 faculty per subtopic.
9. `--dry-run`: skip DynamoDB writes, print what would be written.
