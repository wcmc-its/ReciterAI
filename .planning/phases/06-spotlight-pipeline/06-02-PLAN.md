<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DynamoDB TOPIC# items → pool_ranker → PoolEntry | TOPIC# attributes are LLM-generated (synopsis, impact_justification) but pool ranker treats them as opaque text — it only reads `impact_score` (numeric), `year` (numeric), and `primary_subtopic_id` (string). Synopses pass through unmodified to the assembler. |
| boto3 default credential chain → pool_ranker._get_default_client() | AWS creds via env vars from `~/.zshrc`. Code never reads or displays the file or interpolates the values. |
| Untrusted PMIDs / subtopic_ids → defaultdict keys → log lines | A maliciously crafted PMID could in theory inject log noise; pool ranker just aggregates them numerically. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Tampering | impact_score parsing | mitigate | `float(item.get("impact_score", {}).get("N", "0"))` defaults to 0.0 on missing; pool ranker excludes zero-score rows so a missing field cannot inflate scores. Acceptance criterion test 5 verifies this. |
| T-06-02-02 | Information Disclosure | log lines | mitigate | The single log line emits only `len(result)`, `cutoff_year`, and `top_score` (a number). No subtopic_id, no PMID, no synopsis text. CLAUDE.md security: no credential values logged. |
| T-06-02-03 | Denial of Service | full-table Scan cost | accept | Per RESEARCH §Pitfall 1, Scan over ~30K records is acceptable (~30s, ~$0.10 per scan) and runs once per `--publish` (weekly cadence). Caching to `./out/pool-{date}.json` for `--regen-only` is Plan 06-06's responsibility. |
| T-06-02-04 | Tampering | deterministic sort | mitigate | SPOT-02 is enforced by the tuple sort key `(-score, subtopic_id)`. Acceptance criterion grep-asserts the literal `sorted(.*key=lambda.*-` pattern. Test 3 verifies tiebreaker behavior on synthetic equal-score data. |
| T-06-02-05 | Spoofing | mocked DynamoDB in tests | accept | Tests inject a fake client; production code uses the lazy default-credential client. Acceptance criterion verifies `_default_client is None` after import (lazy init invariant). |
| T-06-02-06 | Information Disclosure | personIdentifier flowing through Paper | accept | `Author.person_identifier` carries the WCM faculty UID (e.g. `m12345`) which is the institutional identifier — not a secret per CLAUDE.md naming convention. The string `"cwid_"` is forbidden in Phase 6 code; if a TOPIC# row has the legacy prefix, the data flows through unchanged (extraction is downstream's job in Plan 06-06). |
| T-06-02-07 | Tampering (PMID dedup bypass) | seen_pmids_per_sub | mitigate | Test 6 asserts a single PMID across 3 TOPIC# rows under the same subtopic counts ONCE. Without dedup, popular publications would inflate impact scores and skew the pool. |
</threat_model>
