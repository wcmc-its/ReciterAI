SubtopicMeta carries the fields needed for sensitive-tag matching. Loaded by Plan 06-05's lede generator from the hierarchy artifact (since pool_ranker only knows subtopic_id + parent_topic). For this plan, treat SubtopicMeta as a small dict / NamedTuple shape:

```python
# Either pass the dict directly, or define a NamedTuple in spotlight/sensitive_gate.py:
class SubtopicMeta(NamedTuple):
    subtopic_id: str
    label: str
    description: str
    parent_topic_label: str
```

SPOTLIGHT_CONFIG#sensitive_tags item shape (per docs/spotlight-dynamodb-schema.md):
```
PK: "SPOTLIGHT_CONFIG#sensitive_tags"
SK: "CONFIG"
tags: List[Map] where each Map = {pattern: S, match_type: S in {substring, glob, regex}, reason: S}
```

SPOTLIGHT_REVIEW shape (per docs/spotlight-dynamodb-schema.md):
```
PK: "SPOTLIGHT_REVIEW#{publish_id}"
SK: "SUBTOPIC#{subtopic_id}"
publish_id, subtopic_id, parent_topic, lede_text, flag_reason ∈ {critic, sensitive_tag, both},
critic_verdict (Map, optional), sensitive_tag_matched (S, optional), papers_used (List[S]),
regen_count (N), attempts (List[Map], optional), status ∈ {pending, approved, rejected},
reviewer (S, optional), reviewed_at (S, optional), created_at (S)
```

Status state machine: only `pending → approved` and `pending → rejected` transitions allowed. The reverse transitions (approved → pending, etc.) are NOT supported in v1; if needed, the operator deletes and re-creates.

ISO 8601 UTC Z format used for all timestamps (mirrors Phase 5):
`datetime.now(timezone.utc).isoformat(timespec="seconds").replace("+00:00", "Z")`
