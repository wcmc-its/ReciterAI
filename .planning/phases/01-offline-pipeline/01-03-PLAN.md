<objective>
Build the publication scoring pipeline that extracts ~10K publications from ReciterDB and scores them against the frozen taxonomy via two-pass Bedrock calls (Haiku screening + Sonnet dense scoring).

Purpose: This is the most expensive and time-consuming step in the pipeline (2-4 hours, ~$35 Bedrock costs). It produces the scored publication data that load_dynamodb.py will load into the chatbot table. The processing tracker in DynamoDB enables checkpoint/resume so the pipeline can survive interruptions.

Output: `score_publications.py` that scores all publications and stores results + processing state in DynamoDB. Intermediate output files `scoring_results.json` and `faculty_metadata.json` for the load step.
</objective>

**Phase 1 -- Extract publications from ReciterDB (PIPE-01, PIPE-02, PIPE-05):**

Function `extract_publications() -> list[dict]`:
- Connect using `get_db_connection()`
- Execute `PUBLICATION_EXTRACTION_SQL`
- Return list of dicts with keys matching SQL aliases: pmid, title, abstract, journal, pub_year, synopsis, impact_score, cwid, name, department, h_index
- Print: "Extracted {N} publications from ReciterDB"
- Group by pmid (a publication may appear multiple times if multiple faculty are first/last author) -- for scoring, deduplicate by pmid but keep all cwid associations in a separate dict

Function `extract_faculty_metadata() -> dict`:
- Connect using `get_db_connection()`
- Execute `FACULTY_METADATA_SQL`
- Return dict keyed by cwid: `{cwid: {"name": ..., "department": ..., "h_index": ..., "article_count": ..., "first_author_count": ..., "last_author_count": ...}}`

**Phase 2 -- Two-pass Bedrock scoring (PIPE-03, PIPE-04, PIPE-06):**

Function `make_screening_prompt(pub: dict, taxonomy: dict) -> str`:
- Use the exact prompt from RESEARCH.md Code Examples "Screening Prompt (Haiku, One Call Per Publication)"
- Include publication title, abstract (if available), and synopsis (if available, per PIPE-05)
- List all topics from taxonomy with id, label, description
- Request JSON: `{topic_id: score}` for all 50 topics

Function `make_dense_prompt(pub: dict, passed_topics: dict, taxonomy: dict) -> str`:
- Similar to screening but ONLY include topics that passed 0.3 threshold
- Ask for more calibrated scoring (0.0-1.0) with justification
- Request JSON: `{topic_id: {"score": float, "rationale": "brief explanation"}}`

Function `score_one_publication(pub: dict, bedrock: BedrockClient, taxonomy: dict, dynamo_client, table_name: str) -> ScoringResult`:
- Create ScoringResult from pub dict
- Mark processing as "pending" via `mark_processing(dynamo_client, table_name, pub['pmid'], 'pending', taxonomy['taxonomy_version'])`
- **Screening (Haiku):** Call `bedrock.call_json(model=HAIKU_MODEL, messages=[{"role": "user", "content": make_screening_prompt(pub, taxonomy)}])`
- Parse screening result as `{topic_id: float_score}`. Filter topics >= 0.3 threshold
- Mark processing as "screened" with `screening_passed_topics` list
- If no topics pass threshold, mark as "complete" and return (publication is not relevant to any topic)
- **Dense scoring (Sonnet):** Call `bedrock.call_json(model=SONNET_MODEL, messages=[{"role": "user", "content": make_dense_prompt(pub, passed_topics, taxonomy)}])`
- Parse dense result. Store dense scores on ScoringResult
- Mark processing as "complete" with scored_at timestamp
- On ANY exception: catch, mark processing as "failed" with error message and retry_count, set result.status = "failed", result.error = str(e)
- Return ScoringResult

**Phase 3 -- Async concurrent scoring with checkpoint/resume (D-09, D-10, D-11):**

Function `get_unscored_publications(publications: list[dict], dynamo_client, table_name: str) -> list[dict]`:
- Extract all pmids from publications
- Call `get_processing_status(dynamo_client, table_name, pmids)`
- Return only publications whose pmid has no status or status != "complete"
- Print: "Skipping {N} already-scored publications, {M} remaining"

Async function `score_batch_async(publications: list[dict], bedrock: BedrockClient, taxonomy: dict, dynamo_client, table_name: str, concurrency: int = 15) -> list[ScoringResult]`:
- Create `asyncio.Semaphore(concurrency)` (per RESEARCH.md Pattern 7)
- Create tqdm progress bar with total=len(publications), desc="Scoring publications"
- Track success_count and failure_count
- For each publication, create async task:
  ```python
  async def score_one_async(pub):
      async with semaphore:
          result = await asyncio.to_thread(score_one_publication, pub, bedrock, taxonomy, dynamo_client, table_name)
          if result.status == "failed":
              failure_count += 1
          else:
              success_count += 1
          pbar.update(1)
          pbar.set_postfix(ok=success_count, fail=failure_count)
          return result
  ```
- Gather all tasks with `return_exceptions=True`
- Filter out exceptions (log them)
- Return list of ScoringResults

**Main function `main()`:**
- Parse optional args: `--test N` (score only first N publications for testing, per D-14), `--concurrency N` (default 15)
- Load taxonomy from `taxonomy_v1.json` -- assert file exists, assert `taxonomy_version` key present
- Initialize BedrockClient and DynamoDB client
- Extract publications from ReciterDB
- Extract faculty metadata (for later use in load step)
- Apply checkpoint/resume: filter to unscored publications only
- If `--test` flag, truncate to first N publications
- Run async scoring batch
- Print summary:
  - Total publications: N
  - Successfully scored: M
  - Failed: F
  - Failure rate: F/(M+F) * 100%
  - If failure rate > 1%: WARNING "Failure rate exceeds 1% target (D-11)"
- Save scoring results to `scoring_results.json` (intermediate file for load_dynamodb.py):
  - List of dicts with pmid, cwid, dense_scores, screening_scores, synopsis, title, journal, pub_year, impact_score, department, name, h_index
  - Only include publications with at least one dense score (status == "complete" and has dense_scores)
- Save faculty metadata to `faculty_metadata.json`
- Print: "Results saved. Run load_dynamodb.py next."

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Script -> ReciterDB | Read-only extraction of publication data and faculty metadata |
| Script -> AWS Bedrock | Publication titles, abstracts, synopses sent to Haiku/Sonnet for scoring |
| Script -> DynamoDB | Processing tracker records written; scored results saved locally |
| Local filesystem | scoring_results.json and faculty_metadata.json contain faculty names, publication data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | score_publications.py | mitigate | Publication abstracts and synopses sent to Bedrock are publicly available academic content (PubMed). Faculty CWIDs are internal identifiers, not PII. DB credentials via env vars only. |
| T-03-02 | Information Disclosure | scoring_results.json | mitigate | Local file contains faculty names and publication data (public info). File not committed to git (.gitignore). No credentials in output files. |
| T-03-03 | Denial of Service | score_publications.py | mitigate | asyncio.Semaphore(15) limits concurrent Bedrock calls. Exponential backoff in bedrock_client handles throttling. Verified Bedrock quota is 10,000 RPM -- 15 concurrent calls is well within limits. |
| T-03-04 | Tampering | DynamoDB PROCESSING# records | accept | Processing tracker is operational state, not security-critical. Malicious modification would cause rescoring (cost impact) but not data integrity issues. IAM credentials required for write access. |
| T-03-05 | Integrity | Scoring results | mitigate | taxonomy_version field on every processing record traces which taxonomy version produced each score. Enables full re-scoring if taxonomy is updated. |
</threat_model>
