**3. Create `utils/bedrock_client.py`** -- port from CViche's `llm_client.py` (per D-04):

The module must contain a `BedrockClient` class with:

- `__init__(self, region=None)`: Lazy client initialization. Read region from `AWS_DEFAULT_REGION` env var if not passed. Do NOT create the boto3 client in __init__; create it on first call.

- `_get_client(self)`: Lazy init of `boto3.client('bedrock-runtime', region_name=self.region)`. Cache on self.

- `RETRYABLE_CODES`: Class constant set = `{"ThrottlingException", "ModelTimeoutException", "InternalServerException", "ServiceUnavailableException"}` (ported from CViche lines 54-58).

- `call(self, model: str, messages: list[dict], system: str = None, max_tokens: int = 4096, temperature: float = 0.0) -> dict`: Main entry point. Translates messages from OpenAI-style format to Bedrock Converse API format. Calls `_call_with_retry`. Returns the parsed text content from the response.

- `call_json(self, model: str, messages: list[dict], system: str = None, max_tokens: int = 4096, temperature: float = 0.0) -> dict`: Calls `call()`, strips markdown fences (`re.sub(r'```json\n?|\n?```', '', content).strip()`), parses JSON. On `json.JSONDecodeError`, retries ONCE with a stronger hint appended: "Respond with valid JSON only. No markdown fences." (ported from CViche's JSON validation retry pattern, lines 369-389).

- `_call_with_retry(self, model, messages_converse, system_list, max_tokens, temperature) -> dict`: Retry loop up to 3 attempts. On retryable error codes, sleep `min(2**attempt, 30)` seconds. On non-retryable error, raise immediately. Returns raw Converse API response dict.

- `_translate_messages(self, messages: list[dict]) -> tuple[list, list]`: Convert from `[{"role": "user", "content": "text"}]` format to Converse API format: `[{"role": "user", "content": [{"text": "text"}]}]`. Separate out any system message and return as `(messages_list, system_list)` where system_list is `[{"text": "..."}]` or empty list.

Model IDs to use as constants at module level:
```python

SONNET_MODEL = "anthropic.claude-sonnet-4-6"
```

Import only: `boto3`, `json`, `re`, `time`, `logging`, `os` from stdlib. No external dependencies beyond boto3.

Key behaviors ported from CViche:
- Exponential backoff: `time.sleep(min(2 ** attempt, 30))`
- JSON fence stripping: `re.sub(r'```json\n?|\n?```', '', content).strip()`
- Lazy client init (CViche lines 86-99)
- Retryable error code set (CViche lines 54-58)

- `create_chatbot_table(client, table_name=TABLE_NAME)`: Creates the DynamoDB table with:
  - KeySchema: PK (HASH, S), SK (RANGE, S)
  - AttributeDefinitions: PK (S), SK (S), faculty_uid (S), taxonomy_version (S), status (S)
  - BillingMode: PAY_PER_REQUEST (per D-13, on-demand)

  - Catch `client.exceptions.ResourceInUseException` and pass (table already exists)
  - After creation, call `client.get_waiter('table_exists').wait(TableName=table_name)` to block until table is ACTIVE

- `wait_for_table(client, table_name=TABLE_NAME)`: Polls `describe_table` until TableStatus is ACTIVE. Use `client.get_waiter('table_exists').wait(TableName=table_name)`.

- `batch_write(client, table_name: str, items: list[dict])`: Writes items in chunks of 25 using `client.batch_write_item()`. Each chunk: `RequestItems={table_name: [{"PutRequest": {"Item": item}} for item in chunk]}`. Log count of items written.

- `make_score_sk(score: float, pmid: str) -> str`: Returns `f"SCORE#{str(min(int(score * 1000), 9999)).zfill(4)}#ACTIVITY#pmid_{pmid}"` (per Research Pattern 2, handles score=1.0 edge case with min(..., 9999)).

- `mark_processing(client, table_name, pmid, status, taxonomy_version, **kwargs)`: Writes a PROCESSING# record: `PK=f"PROCESSING#pmid_{pmid}"`, `SK="STATUS"`, status field, taxonomy_version field, plus any kwargs (e.g., screened_at, scored_at, screening_passed_topics, retry_count, error).

- `get_processing_status(client, table_name, pmids: list) -> dict`: BatchGetItem for list of pmids, returns `{pmid: status_string}` dict. Used for checkpoint/resume (D-09).

- `PUBLICATION_EXTRACTION_SQL`: The corrected SQL using `external_id` for the synopsis join (per RESEARCH.md A6 correction and verified schema: `reciterai_synopsis.external_id` is varchar(50), maps to PMID for publications):
```sql
SELECT DISTINCT
    a1.pmid,
    a1.articleTitle AS title,
    r.abstractVarchar AS abstract,
    a1.journalTitleVerbose AS journal,
    a1.articleYear AS pub_year,
    s.synopsis,
    i.impactScore AS impact_score,
    a.personIdentifier AS cwid,
    asp.name,
    asp.primaryDepartment AS department,
    asp.hIndex AS h_index
FROM analysis_summary_article a1
JOIN analysis_summary_author a ON a.pmid = a1.pmid
JOIN identity id ON id.cwid = a.personIdentifier
JOIN analysis_summary_person asp ON asp.personIdentifier = a.personIdentifier
LEFT JOIN reporting_abstracts r ON r.pmid = a1.pmid
LEFT JOIN reciterai_synopsis s ON s.external_id = CAST(a1.pmid AS CHAR)
    AND s.entity_type = 'publication'
LEFT JOIN reciterai_impact i ON i.entity_id = CAST(a1.pmid AS CHAR)
    AND i.entity_type = 'publication'
WHERE a1.publicationTypeCanonical = 'Academic Article'
    AND a.authorPosition IN ('first', 'last')
    AND a.userAssertion IN ('ACCEPTED', 'ASSERTED')
    AND id.fullTimeFaculty = 'yes'
ORDER BY a1.pmid
```

```sql
SELECT
    asp.personIdentifier AS cwid,
    asp.name,
    asp.primaryDepartment AS department,
    asp.hIndex AS h_index,
```

- `TOOL_EXTRACTION_SQL`: SQL for extracting keyword relevance data for TOOL# records (resolving RESEARCH.md Open Question 4). Based on the verified schema (`reciterai_keyword_relevance` has: entity_type, entity_id, external_id, keyword, relevanceScore as int 0-100):
```sql
SELECT DISTINCT
    kr.external_id AS pmid,
    kr.keyword AS tool_id,
    kr.relevanceScore AS relevance_score_raw,
    a.personIdentifier AS cwid
FROM reciterai_keyword_relevance kr
JOIN analysis_summary_author a ON CAST(a.pmid AS CHAR) = kr.external_id
JOIN identity id ON id.cwid = a.personIdentifier

    AND a.authorPosition IN ('first', 'last')

```
